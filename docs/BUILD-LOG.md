## Rules for every agent

1. Before starting: read "Current state" and "Next" below, and your wave's row.
2. Touch only the files your brief says you own.
3. When done: end your report with a `LOG ENTRY:` block (date, wave, agent label, files changed, how verified with commands + result, what is left; under 10 lines). Agents running in parallel do NOT edit this file themselves (concurrent edits clobber each other); the main session appends every entry. A single agent working alone may append directly.
4. Never edit someone else's log entry. Never delete history. Fix mistakes with a new entry.
5. If you are blocked, say so under `BLOCKED:` in your report (what you need), then stop that part.
6. Shared resources are serialized: in a parallel wave, builders do NOT run `pnpm e2e`, `pnpm test:e2e` or `pnpm build` (they share ports 8100/3101/2526, the `enroute_test` DB and build folders). Builders run `pnpm lint`, unit tests and `node --check`; the wave's check stage runs the full suite once.

## How to run locally

| What | How |
| --- | --- |
| Database | Local Postgres on 5432: db `enroute`, user `enrouteDb` / `enroute09832`. Migrate: `cd backend && ./node_modules/.bin/drizzle-kit migrate` |
| Mail | `cd backend && pnpm dev:mail` (sink on 127.0.0.1:2525). Login codes also print as `[DEV] Login code for ...` in the backend log (this session writes it to its scratchpad `backend.log`) |
| Backend | `cd backend && EMAIL_HOST=127.0.0.1 EMAIL_PORT=2525 EMAIL_SECURE=false EMAIL_USER=dev EMAIL_PASSWORD=dev FRONTEND_URL=http://localhost:3001 node src/index.js` → :8000 |
| Frontend | `cd frontend && pnpm dev --port 3001` (port 3000 is used by another project on this machine) |
| Demo logins | `admin@enroute.local` / `Admin@12345`; `customer@`, `transporter@`, `transporter2@`, `fleetowner@`, `broker@` `enroute.local` / `Demo@12345`. `cd backend && pnpm seed:demo` fills every screen (live/closed/completed loads, trips in every state, offers, RFQs, a contract, plans, subscriptions, a payment to review); safe to re-run |

`backend/.env` holds real Hostinger SMTP and R2 keys. The run command above overrides email so no real mail goes out. Never commit `.env`.
